# Dify 工作流（Chatflow）导入说明

本目录包含项目的 Dify 应用定义，可直接导入到你的 Dify 实例：

| 文件 | 说明 |
|---|---|
| `chess-analysis-agent.chatflow.yml` | Dify DSL（`version: 0.7.0`，Dify 1.x 通用），含 11 个节点 / 10 条连线 |

## 工作流结构

```
用户输入 ──▶ 文档提取器 ──▶ 条件分支（输入是否含着法特征 "1. " ?）
                              │
        ┌─────────────────────┴──────────────────────┐
        │ IF：棋谱分析                                 │ ELSE：理论问答
        ▼                                            ▼
     提取 PGN                                     知识检索
        ▼                                            ▼
  analyze_game（MCP 工具）                        LLM 2（qwen2.5:7b）
        ▼                                            ▼
   整理引擎摘要                                    直接回复 2
        ▼
  LLM（Qwen/Qwen3.5-27B）
        ▼
     直接回复
```

**引擎算棋、模型讲棋**：`整理引擎摘要` 代码节点把冗长的逐着数据压缩成一份摘要
（对局概要 + top 分歧点 + 改进建议素材），LLM 节点的上下文只绑定这一份摘要，
并在系统提示词中硬性约束"只依据给定数据作答，禁止编造"。

## 导入步骤

1. Dify 工作台 → **工作室** → **创建空白应用** 或直接 **导入 DSL**
   （Dify 1.x：工作室右上角 `…` → 导入 DSL 文件）
2. 选择本目录的 `chess-analysis-agent.chatflow.yml`
3. 导入后会提示缺少依赖，按下表逐项补齐

## ⚠️ 导入后必须重新配置的地方

DSL 里的**节点结构、提示词、代码节点**都可以直接复用，但以下几项绑定的是原作者的实例，
必须改成你自己的：

| 位置 | 需要改什么 |
|---|---|
| **LLM 节点 / LLM 2 节点** | 重新选择模型。原作者用的是 `Qwen/Qwen3.5-27B`（OpenAI 兼容接口）与 `qwen2.5:7b`（Ollama）；你需要先在「集成 → 模型供应商」里配好自己的模型，再回来选 |
| **analyze_game 工具节点** | 把 MCP 服务地址改为你自己的 `http://host.docker.internal:9002/sse`（Dify 在容器里就用这个地址；Dify 跑在宿主机上则用 `http://127.0.0.1:9002/sse`），并重新授权 |
| **知识检索节点** | 重新绑定你自己的知识库（可以是 Dify 内置知识库，也可以是经「外部知识库 API」接入的 RagFlow 知识库） |
| **文档提取器节点** | 若不用文件上传，可保留（本项目的条件是"用户粘贴 PGN 文本"，文件上传只是可选入口） |

改完后点右上角 **发布** 才会生效。

## 关于条件分支

分支判断用的是**文本特征**而不是文件类型——因为 Dify 文档提取器的文件类型白名单不含棋谱格式
（`.pgn` 会被拒绝）。所以流程是：用户把 PGN 粘贴进对话框 → 条件分支检查输入是否含着法特征
（如 `1. `）→ 走「棋谱分析」或「理论问答」。

## 常见导入报错

- **`No user query found in messages` (20015)**：使用硅基流动等 OpenAI 兼容接口时，
  平台要求 `messages` 中必须包含 `user` 角色消息。本 DSL 的 LLM 节点提示词里已加了一条
  user 角色消息（内容为 `{{#sys.query#}}`），若导入后仍报错，检查这条消息是否还在。
  → 详见 [`../docs/TROUBLESHOOTING.md`](../docs/TROUBLESHOOTING.md) 第 6 节
- **知识检索返回空**：确认知识库已绑定且文档已完成向量化，另外知识库内容变更后需**重新发布应用**。
- **工具节点报连接失败**：确认 MCP 服务已启动（`scripts/start_mcp.*`），
  且 Dify 能访问到该地址（容器内用 `host.docker.internal`）。
